# 原作分析与还原工作流：八项初步能力

这版是 PIXEL WORLD 主项目的统一功能版，保留零AI内置版本及原有创作流程。八项能力均有编辑入口、GameSpec数据与运行实现；原作特定行为的等价还原需要逐项对照，不能用测试数量代替原作验收。

## 功能入口

| 能力 | 主页面操作 | 运行与保存 |
| --- | --- | --- |
| 原作分析与需求锁定 | AI策划 → 原作分析与需求锁定 | 六类需求；必须还原、可自由生成、暂不支持；证据与确认绑定当前规则。Agent不能替用户确认。 |
| 精确地图 | AI策划 → 精确关卡地图 | 拖动、坐标尺寸、JSON导入导出；显式地图绕过自动排布。GameMaker参考JSON可选碰撞层转换。 |
| 角色物理 | AI策划 → 角色物理 | 速度、加速度、重力、理论目标跳高、空中控制、跳跃次数、松键与助跑；网页/离线共用规则。实际高度受离散时间和碰撞影响。 |
| 机关与状态 | 地图编辑 → 新增对象 | 横纵移动平台、延迟陷阱、冰冻和反转；持续/冷却、挤压、暂停与死亡重置。 |
| 多角色 | AI策划 → 角色池 | 最多8角色，独立物理/生命/碰撞框/近远程倍率/素材动作；C或按钮切换；保留、轮换、加权复活。 |
| 敌人与Boss阶段 | AI策划 → 敌人/Boss阶段编排 | 最多16阶段，触发距离、预警/动作/冷却、路径/拉伸/追踪、攻击及生命转换；支持死亡后危险末阶段。 |
| 原图与动画 | 素材工坊或成品预览 → 批量原图 | 每批32图、40MB；横条、网格、散帧，帧序/FPS/循环与整组预览；原始字节和逐页指纹保持。 |
| 存档与还原对照 | 地图中的存档点；试玩时导出轨迹；成品预览 → 试玩对照 | 恢复点、角色与状态规则明确；轨迹按关卡/片段显示跳跃、死亡、存档及阶段，支持两份JSON比较。 |

## 一个项目的完整操作

1. 填名称、故事，用内置规则或已获准的模型整理草案。在原作分析中记录来源和未知项。
2. 调整地图、角色、机关、物理与行为。应用地图会同步实体数量；原有故事任务若与地图不符，需在故事与任务编辑中修正，系统不会暗中删除故事要求。
3. 本地规则检查后确认规格。必须还原项需要人工对照证据；改变规则后重新确认。
4. 准备原图或其他素材。原图导入不调用AI，也不会自动公开上传。角色池可引用不同已启用的图片素材及其动作。
5. 左栏选择“上传自己的图片”，用已上传素材创建游戏。已有素材不足时可明确使用内置素材补齐；内置创建仍是零API路径。
6. 试玩、保存、刷新恢复、重试与通关。在需要的节点导出试玩轨迹。
7. 右栏导出游戏ZIP。该包包含当前GameSpec、原图、共享离线引擎及本地资源。
8. 用“重新编辑已导出的项目ZIP”重新载入原生ZIP（45MB以内）。只读取数据与素材，不执行包内HTML/JS/CSS；导入后重新进行本地检查并等待批准，必须还原项的旧确认被清除。
9. 右栏“试玩对照”可载入两份轨迹，选择关卡和片段查看路线及事件。相同规则身份才计算按片段时间对齐的位置差；这些数值不是自动合格证明。

## 恢复规则

关内重试保留最近存档点，满血复活，重置本关敌人、机关、收集品、任务进度与得分，并按配置选择角色。刷新恢复则保留存活会话、仿真时间、状态剩余时间、阶段、角色选择和抽取种子。切换角色不会回血或刷新攻击冷却；碰撞框放不下时拒绝切换。

自动生成的旧模板保留其Boss规则；显式地图可以没有最终Boss。自定义地图、物理、角色池或阶段程序的数值经过Agent检查与存储迁移时按玩家设定保留，并接受运行边界检查。

## IWBTZ参考的真实边界

- 已读取GameMaker对象/精灵/房间/tileset元数据。支持本资料中格式1瓦片RLE的严格尺寸解码；该编码来自本机数据推断，不保证其他GameMaker版本通用。
- 仅转换选定整格碰撞，不执行GML、房间创建代码、动态改图或自动映射全部实例。出生和出口需要明确指定；遗漏及裁切有报告。
- Regular/Ball的移动参数、原图和食人花阶段结构提供参考。原作7角色的所有特殊攻击、食人花独立头身、圆形判定、完整音效和原作事件恢复尚未宣称等价还原，应标“暂不支持”或列具体待对照规则。
- 联合验收项目用于覆盖八项工具能力，地图和Boss程序是测试配置。它不冒充IWBTZ完整成品。

## 部署与证据

完整站点是Next.js项目：`npm ci`、`npm run build`、`npm start`，或由Vercel构建。已有Vercel环境变量继续按原项目配置；包内不含真实密钥、依赖或构建缓存。历史UPMA静态简单版仍独立保留，不把源码ZIP当静态部署包。

最终测试、生产构建、实际网页导出、源图字节、轨迹和源码指纹记录在既有留证目录的 `14-八项能力整体验收-20261102`。保留失败过程，最终结论以该目录的验收报告为准。该开发交付不抵扣另行批准的模型付费验收、Supabase双账号权限验收或PICO真机测试。
