# PIXEL WORLD 八项功能完整使用教程

适用版本：2026-11-02八项初步能力整合版。适合先用内置规则、上传原图走通流程，再按需连接已批准的AI模型。八项编辑能力不要求调用AI；登录社区也不是本地制作、试玩和导出的前提。

## 1. 先在Vercel打开新版

### 已有Vercel项目

1. 登录Vercel，进入对应的PIXEL-WORLD项目。
2. 在Settings → Git核对连接仓库为`zbjgrhr/PIXEL-WORLD`，生产分支为`main`。
3. 在Deployments查看这次新提交的构建。若启用Git自动部署，推送会触发构建；以该次部署显示Ready为准。
4. 点开这次部署的地址。若旧页面仍在，硬刷新；先确认部署对应新提交，再排查浏览器缓存。
5. 不要把以前的UPMA静态目录配置套到这个完整Next.js项目。

### 第一次连接Vercel

1. Vercel控制台选择新增项目，从GitHub导入`zbjgrhr/PIXEL-WORLD`。
2. Framework选择Next.js；Root Directory选择仓库根目录，也就是有`package.json`的目录。
3. Build Command为`npm run build`；Install Command可用`npm ci`；Output Directory保持Next.js框架默认，不填`out`或`dist`。
4. 环境变量沿用原项目的Supabase配置。制作本地作品不要求先配置社区；社区使用`.env.example`列出的`NEXT_PUBLIC_SUPABASE_URL`、`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`和服务端`SUPABASE_SECRET_KEY`。Secret只放服务端环境，不能加NEXT_PUBLIC前缀。
5. 点击Deploy，等待Ready后打开站点。改环境变量后需要重新部署才能应用到新构建。
6. 新域名若需要GitHub登录，检查原Supabase登录回跳配置覆盖这个正式域名。此前localhost登录成功不自动证明新域名配置成功。

Vercel官方说明：[GitHub集成](https://vercel.com/docs/git/vercel-for-github)、[Next.js部署](https://vercel.com/docs/frameworks/full-stack/nextjs)。

## 2. 看懂页面与保存方式

| 区域 | 用来做什么 |
| --- | --- |
| 左栏 | 切换写故事、AI策划、做素材；选择文字/图片来源；执行检查、批准和创建 |
| 中栏 | 填故事、编辑规则、审核规格、逐项准备素材 |
| 右栏 | 已创建的游戏、试玩、导出ZIP、成品素材与轨迹对照 |

先记住两件事：**当前草稿和右栏成品分开保存**。改完草稿要重新检查、批准、创建，右栏成品才更新。右栏显示“这里显示已创建的游戏”时，不能把它当成修改后的新版。

浏览器草稿、作品与素材依赖当前浏览器和网址的本地存储。localhost、Vercel预览域名、正式域名的存储互不相通。换网址、电脑、浏览器前，先导出项目ZIP备份，再在新站导入。GitHub保存的是网站代码，不会自动保存浏览器内的个人作品。社区草稿/附件也不要当作自动同步所有本地编辑的保证。

## 3. 第一次：十分钟走通零付费流程

1. 在“写故事”填名称，如“钟楼试炼”。故事可写：“小骑士穿过机关练习场，击败守门者，找到出口。”设置关卡数量为1。
2. 点击“完成故事，进入AI策划”。选择内置规则路径，运行补全或检查；不配置文字API。
3. 在中栏检查故事、主角、关卡。如果需要改规则，先按下面各章修改。
4. 点击左栏“检查草案并进入审核”（若草案已检查，则直接进入待确认状态）。有阻断提示先处理。
5. 点击“批准规格并开放生图”。这一步批准内容，不会单凭按钮名称就自动扣图片费用。
6. 在“做素材”选择“内置、上传与本机”→“内置像素素材”，点击“用内置素材创建游戏”。这是零AI简单版。
7. 右栏出现游戏后点击“试玩游戏”。试走、跳跃、攻击和重试。
8. 点击“导出游戏ZIP”。保留ZIP，稍后用“重新编辑已导出的项目ZIP”可以继续改。

上传原图时，第6步改为“上传自己的图片”，在中栏准备素材，再点“用已上传素材创建游戏”。不要为测试新编辑器误选付费图片API。

## 4. 原作分析与需求锁定

入口：AI策划 → 中栏“原作分析与需求锁定”。

1. 填“原作名称”和“原作参考来源”，例如IWBTZ及工程/视频说明。填写文件路径只是记录来源，不会让网页自动读取整份本机工程。
2. 点“添加需求”，选择角色、地图、操作、敌人、机关或通关条件。
3. 写明确要求，如“连续两次跳跃，松键降低上升速度”，避免只写“手感一样”。
4. 选还原策略：必须还原＝阻止未经人工确认的批准；可自由生成＝允许按当前方案发挥；暂不支持＝明确能力缺口。
5. 在“需求证据”记录文件/事件/行号或视频时间点。对照当前设定后，才勾“我已用上述依据对照确认当前设定”。
6. 改地图、物理等规则后，旧确认可能失效，需要重新对照。Agent不能替你确认。

“载入IWBTZ已核实的来源条目”适用于清单为空时。条目是起点，不能代表全作已经被自动复制。

## 5. 精确地图：先搭一个能通关的小房间

入口：AI策划 →“精确关卡地图 · 可视编辑与JSON”。

1. 选择要编辑的关卡，设置世界宽高。坐标单位是世界像素，左上角为(0,0)，向右x增大，向下y增大。
2. 例如世界1600×720，连续地面Y=600，网格8。连续地面会铺满该Y以下区域；想做真正深坑，清空连续地面Y，再用平台搭地面。
3. 选`player`，设x=60、y=536、width=32、height=64。这里玩家底部恰好落在600的地面上。
4. 选`exit`，放在右端，如x=1490、y=504、width=64、height=96。出口要可达。
5. 在“新增地图对象类型”选平台，点“新增对象”，选中新对象，填坐标和尺寸；也可在图上拖动矩形，网格控制对齐。
6. 逐步增加敌人、收集品、Boss、陷阱和存档点。用下拉列表准确选择小对象，不必只靠鼠标点中。
7. 点“应用地图并重新审核”。只拖动或修改编辑器中的数字，不等于已经应用到项目。
8. 应用会同步地图中的实体数量；若故事任务仍要求不存在的敌人/物品，需相应修改任务，不能直接忽略检查提示。

“改回自动布局”会回到程序排布。精确地图可以没有Boss，但若地图仍有Boss，按当前通关规则处理Boss后再到出口。

### 地图JSON导入导出

展开“地图JSON导入 / 导出”，可编辑地图JSON，按界面操作载入/应用并下载。先从编辑器导出一份作为格式模板，再改内容。地图JSON只保存地图；完整项目应导出游戏ZIP，规则备份可下载GameSpec。

### GameMaker参考碰撞层

1. 本机源码不能直接拖进地图当完整游戏运行。先在项目仓库终端提取静态参考：

```powershell
node scripts/import-gamemaker-reference.cjs "C:\Users\zbjgr\Desktop\项目源码包\IWBTZ\i wanna be the zomboy_v1\game\Blank Pixel Game(3)\Blank Pixel Game 2" "IWBTZ-reference.json"
```

2. 展开地图内“转换GameMaker参考碰撞层”，选择生成的参考JSON（2MB以内）。
3. 选择房间，勾选真正用于碰撞的瓦片层；不要把装饰层都当成实体墙。
4. 明确填写主角出生矩形和出口矩形，点“转换并载入地图编辑器”。
5. 阅读并下载转换报告，处理未转换实例和裁切信息；再点地图的“应用地图并重新审核”。

目前仅支持所给工程已验证的格式1瓦片数据和选定整格碰撞。GML、创建代码、动态改图、所有对象事件及瓦片画面不会自动变成等价游戏，需在编辑器中补齐可支持的内容。

## 6. 可调物理与碰撞框

入口：AI策划 →“角色物理 · 网页与离线共用”。

| 参数 | 调整效果与建议 |
| --- | --- |
| 速度 | 越大移动越快；先小幅调整 |
| 加速度 | 控制达到目标速度的过程；0为直接响应的配置 |
| 重力 | 越大下落更快，同样起跳速度下跳得更低 |
| 起跳速度/理论目标跳高 | 通过速度与重力估算跳高；实际高度还受时间步和碰撞影响 |
| 空中控制 | 控制空中横向输入力度；降低后更难中途修正 |
| 连续跳数 | 1为单跳，2可做双跳 |
| 松键截短 | 提早松开跳跃键，限制上升速度 |
| 助跑 | 调整跑动对跳跃的加成及上限 |

改完应用并重新审核，重新创建后试玩同一段路线。一次改一两个参数更容易判断差异。碰撞宽高在地图玩家矩形或角色池中设置。

**启用角色池后，各角色的独立参数优先**：只改基础主角参数，不一定改变已有角色池成员。需要去角色池选择具体角色调整。

## 7. 机关、状态和存档点

入口：精确地图 → 新增对象类型。新增后选中对象，编辑其专属参数并应用地图。

| 对象 | 怎么设 | 怎么检查 |
| --- | --- | --- |
| 移动平台 | 横向/纵向、位移距离、速度；正负距离决定方向 | 站上看能否承载；侧面推挤；被墙夹住会死亡 |
| 触发陷阱 | 矩形范围、触发延迟、有效持续、冷却，时间为毫秒 | 进入后先等预警，再看有效期；离开后再进入测试重触发 |
| 冰冻 | 范围、持续、冷却 | 进入后观察移动受限，结束后恢复 |
| 方向反转 | 范围、持续、冷却 | 进入后按左右键，结束后确认恢复 |
| 存档点 | 触碰矩形和复活坐标 | 先触碰，再死亡；看是否从新位置满血复活 |

状态区需离开后才可重新触发；暂停会暂停仿真计时。不要把出生点设在致命范围内，也不要把复活点设在墙体内部。

## 8. 多角色与能力差异

入口：AI策划 →“角色池 · 能力与复活规则”。

1. 启用角色池。先编辑第一个角色，再点“复制为新角色”，最多8个。
2. 分别设置名称、生命、速度、起跳速度、独立物理、碰撞宽高。
3. 设置近战/远程倍率，0表示该类攻击禁用；这适合做能力差异，但不自动提供原作特殊攻击逻辑。
4. 在“图像与动作帧条”选择对应素材。先把不同角色图导入不同素材，再让角色引用，避免所有角色共用同一张图。
5. 选择初始角色；按需允许手动切换。
6. 复活规则选保留角色、轮换或按权重抽取。加权模式设置权重和随机种子；权重是相对值，不是直接填百分比。
7. 重新审核、批准、创建。试玩中按C或角色按钮切换，再故意死亡检查复活选择。

切换不会补满血或刷新攻击冷却；目标碰撞框放不下时会拒绝切换。普通角色/Ball移动参考按钮只载入移动参数，不自带原图、原作特殊攻击或已确认的抽取概率。

## 9. 敌人和Boss阶段

入口：AI策划 →“敌人/Boss阶段编排”。

1. 选择Boss或某类敌人，启用阶段程序。
2. 编辑第一阶段名称；设置触发距离，0表示不受距离门槛限制；可要求玩家在上方。
3. 设置预警、动作、冷却时间（毫秒），如500、1500、500；设置重复次数。
4. 选择运动：`still`静止、`offset`位移、`chase`追踪、`stretch`拉伸。根据所选运动设置X/Y位移、追踪速度与半径。
5. 选择攻击：`none`无、`contact`接触、`melee`近战、`ranged`远程；需要时调整攻击间隔。
6. 设置“可受伤”；选择`time`按时间转换，或`health`按生命比例阈值转换，例如0.5对应剩余生命比例的一半。
7. 点“新增阶段”继续编排，最多16阶段。按需循环；设置死亡后移除或保留危险末阶段。
8. 重新审核、创建、试玩。观察预警、实际攻击、冷却、阶段标签和受伤条件；导出轨迹检查阶段事件。

“载入食人花六阶段改编示例”会替换当前目标的阶段配置，操作前先备份GameSpec。该示例移动一个实体，不等价于原作独立头身、圆形判定和全部攻击。

## 10. 批量原图与动画

入口：做素材的素材工坊，或右栏成品预览 →“批量原图 · 保留原始文件”。

1. 选择PNG/WebP/JPEG，一批最多32张、总计40MB；单张最多10MB，尺寸边长不超过4096。
2. 每张选择“目标素材”，再选单张静态或站立/行走/跳跃/近战/远程/受击/死亡动作。
3. 单张静态适合背景、物品或静态角色。动画选择横向帧条、多行图集或散帧文件。
4. 横条填写帧数；图集填写列、行和帧数；散帧把同一动作的所有文件映射到同一素材、同一动作，设置顺序号，可按文件名自然排序。
5. 设置FPS（1～60）、循环，动作最多64帧。自定义帧序从0开始，例如`0,1,2,1`，留空按顺序播放。
6. 点“预览”，确认透明边缘、整组文件顺序、播放速度与循环；橙框只作为源图像素坐标的碰撞参考。
7. 点“应用整批映射”，看到应用并缓存成功后再离开。若提示草稿已变化，重新选文件，避免把旧批次应用到新草稿。
8. 左栏选“上传自己的图片”，点“用已上传素材创建游戏”。缺项可明确用内置素材补齐。

实际碰撞框在地图/角色池设置；预览橙框不会自动修改碰撞。一次性动作可能被游戏动作窗口截短。原图保持字节和来源指纹，不强制AI重画；应用和导出会使用这些原图。

## 11. 试玩、存档恢复与轨迹对照

移动用A/D或左右方向键，跳跃用W/Space/↑；近战J、远程K；启用切换时C切角色。游戏内也提供操作按钮，以页面提示为准。先点击游戏区域获取焦点；切到后台会暂停。

### 区分三种动作

| 动作 | 结果 |
| --- | --- |
| 触碰关内存档点 | 更新最近复活位置 |
| 死亡/关内重试 | 保留最近存档点，满血，重置本关敌人、机关、物品、任务与分数，按角色复活规则选择角色 |
| 刷新恢复会话 | 恢复保存的仿真、角色、阶段和状态剩余时间；不是一次死亡重置 |

试玩界面可选择是否保留本地轨迹，点“导出试玩轨迹”保存JSON。记录有容量上限，长时间试玩可能丢弃早期样本，查看界面的丢弃提示。

右栏展开“试玩对照 · 轨迹、死亡与阶段”，选择1～2份轨迹JSON（每份最多2MB），选择关卡和片段。图中查看路径、跳跃、死亡和存档点，展开事件记录查看Boss阶段。规则身份相同才计算按片段时间对齐的位置差；平均距离小不代表原作已经还原成功。

建议固定一条测试路线：出生→第一次跳跃→存档点→死亡→恢复→Boss阶段→出口。改参数前后都走这条路线，保存两份轨迹和对应GameSpec，避免把不同地图误当作同一测试。

## 12. 导出、离线运行、继续编辑

1. 右栏“导出游戏ZIP”导出的是当前成品。改了草稿而未重新创建时，导出的仍是旧成品。
2. ZIP包含GameSpec、素材和离线运行资源。解压到独立文件夹，从包内HTML入口运行；不要直接在压缩预览中打开。若浏览器限制本地文件，可用本机静态服务器打开整个解压目录。
3. “下载当前草稿GameSpec”适合备份和核对数据，但完整素材搬迁优先用游戏ZIP。
4. 在新网址中展开“重新编辑已导出的项目ZIP”，选Pixel World原生ZIP（45MB以内）。
5. 重新载入后会撤销旧批准和必须还原项的确认。再次对照、检查、批准，然后用原素材创建；无需重新调用AI。
6. 定期按日期保存ZIP、GameSpec、轨迹。不要直接覆盖唯一备份。

网站源码ZIP用于部署整个制作器；游戏ZIP用于运行/重开一个作品；地图JSON用于编辑一关；轨迹JSON用于观察一次试玩。四者用途不同。

## 13. 常见问题

| 问题 | 处理 |
| --- | --- |
| 找不到新编辑器 | 核对Vercel提交版本；进入AI策划阶段并展开相应折叠项 |
| 按钮灰色 | 等当前任务结束；检查必填项、阻断提示、是否未批准；先完成当前阶段 |
| 修改后试玩仍旧 | 重新检查→批准→创建；确认右栏所选作品正确 |
| 修改基础速度不生效 | 检查是否启用角色池，去改该角色自己的数值 |
| 无法批准 | 检查必须还原项的证据/人工确认、地图/任务矛盾和素材缺项 |
| 动画乱序/只见一帧 | 核对目标素材与动作、横条/图集/散帧模式、顺序号、帧数、FPS和循环 |
| 碰撞框与原图不符 | 在地图/角色池改实际尺寸；原图预览橙框只是参考 |
| 新Vercel网址作品消失 | 原网址本地存储独立；回原网址导出ZIP，在新网址导入 |
| GameMaker导入后少对象 | 查看未转换实例报告；当前只转换选定碰撞层，手动补支持的对象 |
| 两份轨迹不能算差异 | 规则身份不同；可分别观察，但不能直接当同规则比较 |
| ZIP导入失败 | 使用原生游戏ZIP，检查45MB限制和完整性；网站源码ZIP不能作为游戏导入 |
| 社区登录/上传失败 | 与本地制作分开排查，检查正式站Supabase变量、回跳与上传配置；不要清空唯一作品备份 |
