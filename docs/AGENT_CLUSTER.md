# Pixel World Agent Cluster

## 目标与边界

Agent Studio 将游戏构想拆成多个职责清晰的短任务，并把最终结果收敛为现有引擎可以直接读取的 GameSpec V3。Agent 只能生产结构化数据，不能生成、执行或修改 JavaScript、API 配置与导出代码。图片生成仍由已有素材队列负责，且必须经过用户批准。

## 受控 DAG

```text
Director ─ Narrative ─┬─ Mechanics ────┐
                      └─ Art Director ┼─ Level Designer ─ 程序整合 ─┬─ 综合评审 ─┐
                                                                     └─ 引擎规则 ─┼─ 定向修订
                                                                                     └─ (最多第二轮)
Revision ─ Asset Coordinator ─ 用户批准 ─ 图片素材队列
图片完成 ─┬─ Visual QA ─┐
          └─ Playtest ──┼─ Publisher Report
```

浏览器按依赖顺序调度，每次最多并发三个文字 Agent；服务端接口一次只执行一个任务，避免长请求。已经成功且输入摘要未变化的任务不会重复执行。手动重跑上游任务时，其下游任务和旧成果会一并失效，防止混用不同版本的规划。

中栏修改后，按字段确定受影响职责及其依赖：故事/人物从故事策划更新，玩法数值从玩法设计更新，关卡/任务从关卡设计更新，画风从美术更新；整合、评审、修订与素材统筹随依赖更新。名称、原始故事、整体要求或关卡数改变时重新处理整条策划链。锁定条件变化也会重新整合与评审。

不受影响的成功任务保留原结果、输入摘要和用量；待更新的任务不自动调用模型。玩家点击“更新受影响的任务”后沿用原模型锁定继续，也可以只用本地规则检查草案进入人工审核。修改后必须重新批准。旧任务的结果及用量保留在修改前记录中，旧视觉/试玩/发布报告会撤销；第二轮任务也能正确重试。恢复同一草稿时，可重新接回暂停的运行与保留成果。

界面显示十个专业职责：创意导演、故事与角色策划、玩法设计师、关卡设计师、美术指导、素材与动画统筹、综合评审、定向修订、视觉验收和试玩验收。保留旧任务 ID 以兼容历史运行；`integrator`、`engineQa` 和 `publisher` 是程序步骤，不计作额外专业 Agent，也不额外调用文字模型。无问题的修订直接复用当前规格。

## 叙事与编辑

`NarrativeSpec` 包含故事起因、动机、冲突、Boss 关系、结局、人物关系、线索与回应，以及按稳定关卡 ID 关联的剧情、交互点与任务。玩家原始故事和锁定文字独立保存。中栏可编辑故事、人物、线索、关卡、任务和美术；局部优化限定修改组，补全空缺保留已有内容。任何内容变更都会撤销旧审批。

文字模型改动明确填写或锁定的叙事字段时，原文继续生效，改动进入逐项对照。完整故事的核心叙事字段也会进入这项保护。玩家可采用、保留，或全部保留；未处理的建议会阻止批准。采用后记录为玩家确认的文本，更新相应原文锁定，并要求重新检查。手动编辑后，引用旧值的建议标为过期，不能覆盖新内容。

单纯保留原文只更新决定记录，保留当前运行、成功任务、用量和模型锁定，不改动游戏内容或存档标识。待选建议不会进入其他 Agent 的共享事实。此保护依赖明确字段和原文锁定，不能据此声称程序已理解自由故事中的每项隐含事实；仍需综合评审和玩家确认故事、关卡是否一致。

新补全若只产生待选建议、没有改动当前文字，也会撤销旧批准并要求玩家决定，但不会重跑已完成任务。来源说明、锁定记录和建议决定不参与可玩故事的存档标识；实际剧情、任务与关键关卡条件仍参与。审批期间防止重复提交，并在恢复图片缓存后再次核对当前输入，避免批准已被修改的旧版本。

本地完整故事会把明确标注“最后、最终、从此”等的结局与开场分开；长故事的开场优先介绍前两句背景及行动目标。原故事保持完整可查看，玩家明确填写的开场仍优先。

在线和离线 ZIP 共用 `createNarrativeEngine`。仅支持真实收集、普通敌人、Boss、抵达地点和对象交互事件；未满足任务条件时出口保持关闭。剧情支持跳过、回看、重试、重开与存档恢复。旧游戏缺少叙事时保持原有通关方式。

## 数据与恢复

- `AgentRun`：运行状态、项目、固定文字模型、轮次、审批状态、任务与成果。
- `AgentTask`：角色、依赖、状态、尝试次数、输入摘要、Token、错误和时间。
- `AgentArtifacts`：创作简报、叙事、玩法、美术、关卡、GameSpec、QA 和发布报告。
- `AgentIssue`：`info / warning / blocking`、来源、GameSpec 路径、说明和建议。

AgentRun 保存在独立 IndexedDB 中。刷新时，未结束的 `running` 任务会安全恢复为 `waiting`，整个运行进入 `paused`，由用户点击继续。图片大数据仍使用原有素材数据库。API Key 不属于任何持久化数据结构。

## 模型锁与接口

`POST /api/agents/execute` 支持 OpenRouter、OpenAI 和 DashScope。启动运行后，平台和文字模型被锁定，所有 Agent 都使用同一模型标识。OpenRouter 使用明确模型而不是自动路由器，以免同一运行切换底层模型。图片平台和图片模型在素材生成区另行锁定。

请求失败策略：认证、余额和参数错误立即停止；超时、限流和服务器错误最多重试一次。JSON 解析失败允许一次结构修复。模型输出会经过角色字段白名单、字符串/数组限制、危险键过滤、GameSpec V3 标准化和确定性引擎检查。

## 审批与质量检查

在评审和修订完成前，Agent 模式不会显示素材生成区。两轮后仍有阻断问题时停止，要求用户调整构想或重新运行相关 Agent。没有阻断项时，用户点击批准才会开放素材卡片和图片 API。

图片生成后，支持图片输入的文字模型最多抽查六张实际图片，包括角色静态参考和行走帧条。报告列出精确素材 ID、已抽查数量及总量；模型没有确认检查的图片不计入覆盖。不支持视觉或没有图片时，只检查素材元数据，明确显示未检查画面。检查绝不会自动重新生成图片。

试玩验收读取当前版本的真实本地运行记录，记录已进入/完成关卡、任务反馈及开场/结局触发。没有证据时为 `not-tested`，部分完成为 `observed-partial`；不接受模型自称“全部通过”作为运行证据。记录仅代表本浏览器实际观察到的进度，不等于默认难度、操作手感、存档恢复和离线导出的全面测试。任务/剧情改变后，旧记录不会用于新版本。检查汇总不会自动批准规格或自动发布游戏。

## 验证命令

```bash
pnpm typecheck
pnpm test
pnpm build
```

测试覆盖 DAG 解锁顺序、发布依赖、龙之城堡五关 GameSpec、缺失素材识别、Agent 字段白名单和无真实额度消耗的 Agent API 模拟请求。网页内“测试 Agent API”用于正式验收时的一次低成本真实调用。
