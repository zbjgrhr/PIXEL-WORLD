# Pixel World：完整叙事与生成质量升级目标

状态：实现与验收进行中。进度及证据见 `NARRATIVE_IMPLEMENTATION_STATUS.md`；下述完整范围保持不变。

## 总目标

玩家只提供几个词、数字或少量灵感时，Pixel World 也能生成具体、连贯、可编辑的完整游戏方案；玩家提供完整故事时，保留核心事实、人物与主题，改善故事因果、人物动机和冒险节奏。故事通过关卡任务、事件反馈和结局落实到实际游戏中。

本次一次完成叙事生成、Agent 协作、字段与审核界面、运行时剧情、任务条件、保存和离线导出。故事完整性、程序可用性、图片质量和真实试玩分别验证。

## 一、输入理解与完整故事

1. 区分玩家原始输入、明确要求、锁定原文、系统补充与生成结果，分别保存来源。玩家原始输入始终可查看。
2. 信息不足时主动补出世界、主角、事件起因、动机、冲突、对手、阶段目标、高潮和结局；数字等信息可以成为标题、地点编号或线索，不能直接拼成整篇故事。
3. 完整故事允许改善表达、衔接与节奏，保持人物身份、核心事件、主题和明确结局。会改变这些设定的建议单独呈现，等待玩家采用。
4. 建立人物关系、关键物品与事件之间的联系。伏笔、线索、人物变化按故事需要安排，并在后文回应；不强制每篇故事都安排反转。
5. 把已选灵感融入世界、角色、目标和关卡，不把内部灵感标记和原始列表直接作为成品故事。
6. 玩家可读的名称、故事、关卡和任务使用自然中文；生成图片所需提示词单独保存，避免英文占位描述混入剧情展示。
7. 本地规则、WebLLM、本机模型和自有文字 API 共用完整性要求。无模型时使用可组合的完整故事与关卡模板；模型失败时保留原有结果，提供合格的本地方案继续审核。

## 二、十个 Agent 贯穿制作过程

| 角色 | 交付物 |
|---|---|
| 创意导演 | 玩家要求、缺项、创作方向、核心特色与可自由补充的范围 |
| 故事与角色策划 | 故事骨架、人物关系、动机、完整剧情及分关叙事 |
| 玩法设计师 | 核心操作、任务条件、胜负条件及引擎支持情况 |
| 关卡设计师 | 各关挑战、布局、难度、阶段目标与故事推进 |
| 美术指导 | 角色固定特征、风格、配色、比例和场景规则 |
| 素材与动画统筹 | 素材、动作、参考关系、复用和预计制作任务 |
| 综合评审 | 内容完整性、故事与玩法对应、灵感落实及明确问题清单 |
| 定向修订 | 对具体问题的修改、影响范围和复核结果 |
| 视觉验收 | 对实际图片与动作的检查及可定位的问题 |
| 试玩验收 | 真实运行、任务触发、关卡出口、Boss、结局与导出验证 |

实施要求：

- 故事骨架、主角目标和事实约束先确定，再展开玩法、美术与关卡。
- 角色共用制作档案，各自负责明确字段，提交定向修改，保护玩家锁定项。
- 规格合并、结构检查和确定性规则优先由程序执行；复用成功结果，仅重跑受到修改影响的步骤。
- 限制自动修订与重试次数，显示实际阶段、结果来源和处理问题；无法解决时明确说明并保留可用结果。
- 一次完整 Agent 运行继续锁定文字模型，图片批次独立锁定图片来源和模型。
- 真实运行和图片检查须有实际证据；缺少条件时明确标记未验证。

## 三、结构化字段与界面

保留桌面三栏、右栏最大、整页滚动、窄屏上下排列、现有奶油与绿色基调。继续由左栏三步导航统一控制流程。

- 左栏显示当前步骤、来源、主要操作与需要处理的问题。
- 中栏分组编辑故事、角色、目标与玩法、关卡、美术和素材。完整提示词保留为高级编辑方式。
- 字段增加事件起因、人物动机、阶段目标、人物关系、Boss 与事件的关系、关键线索及回应、结局方向、实际完成条件和角色固定特征。
- 标明玩家填写、系统补充和原文锁定。支持补全空缺、优化指定部分、锁定要求，并展示修改及其关联影响。
- “一键补全并优化提示词”使用统一链路：理解输入 → 补成完整方案 → 填入字段 → 检查与定向修补 → 展示可审核结果。
- 审核分别显示内容问题、结构问题、引擎支持情况和待人工确认事项，避免把结构通过显示为作品全面合格。
- 修改故事或玩法后撤销相关批准，标记旧成品和待更新结果；配置、成功素材和进行中的任务保持可恢复。

## 四、一次接入完整游戏内叙事

本次包含以下全部环节：

1. 开始游戏前的开场剧情与冒险目标。
2. 各关开始时的地点、阶段剧情和当前任务。
3. 收集关键物品、击败敌人、到达地点和交互事件的剧情反馈。
4. Boss 战前的事件说明与战后的结果反馈。
5. 通关结局，回应最初目标、关键线索与人物变化。
6. 可跳过、可回看的剧情记录；阅读时妥善处理暂停与操作输入。
7. 重试、重新开始、继续游戏时正确恢复或重置任务和剧情触发状态，防止重复发奖、重复播放和提前触发结局。

任务基础能力包含收集、击败指定目标、到达出口或区域、指定对象交互及它们的顺序组合。生成器只使用已实现的条件。背景描述与实际任务分别表达；任务绑定真实对象、计数和事件，完成状态实际控制对应进度或出口。

叙事复用已有角色、背景与素材。新增可生成素材类别时，同步接入素材目录、工坊、生成、上传、缓存和导出。

## 五、数据、兼容与导出

- 叙事与任务进入结构化 GameSpec，包含稳定 ID、关卡引用、触发条件和事件结果。
- 解析、校验、Agent 输出过滤、模板、素材规划、缓存、游戏恢复和 ZIP 导出共用同一数据约定。
- 旧游戏可继续打开与试玩；缺少叙事数据时提供明确的兼容处理。
- 离线 ZIP 包含剧情、任务与已有素材，断网后仍可推进任务、播放剧情并到达结局。
- 叙事新增不引入自动付费生图；图片制作继续要求玩家批准规格并主动操作。

## 六、验收目标与证据

### 生成与内容

- 覆盖纯数字、几个词、短故事、完整故事、已选灵感、锁定字段和互相矛盾的输入。
- 每个合格方案具有具体人物、明确冲突与目标、区分开的关卡、相关敌人与 Boss、可执行任务及回应目标的结局。
- 检查原文拼接、通用占位角色、重复关卡、灵感仅文字出现、故事承诺与引擎能力不符等情况。
- 验证扩写不会被保护逻辑覆盖回原文；系统新增内容不会冒充玩家明确要求。

### 来源与失败恢复

- 验证本地规则、WebLLM 轻量补全、本机模型与自有 API 的数据流和来源标识。
- 覆盖超时、上下文限制、错误 JSON、部分字段缺失与服务不可用；保留已有内容，显示明确恢复方式。
- 验证修改的依赖影响、局部重跑、模型锁定、人工批准和旧结果标识。

### 实际游戏与导出

- 在真实浏览器逐项验证任务完成与未完成、事件顺序、出口门槛、Boss 前后剧情、结局、跳过与回看。
- 验证死亡重试、重新开始、保存恢复和跨关卡状态，确认剧情与任务不会错误重复或提前完成。
- 导出后断网运行，验证同一套叙事与任务链路。

### 工程与显示

- 类型检查、现有测试、必要的新增回归测试和生产构建通过。
- 在桌面、平板和手机宽度以 100% 缩放检查主要流程、文字可读性与控件可达性。
- 验收记录区分真实模型调用、模拟接口、程序规则验证和真实试玩，记录实际耗时及可获得的调用用量。

完成条件：以上生成、界面、运行时、数据兼容、离线导出和验证要求均有当前代码与实际结果证明；仅整理文案或结构检查通过不代表本目标完成。
